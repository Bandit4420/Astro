# Astro 1.1.1 — Discovery request hardening

Includes all Astro 1.1 features: collection search/type filters/sorting, expanded profile charts and favorites, rotating spotlight, continued Explore pagination with quick-add, selectable recommendations, Japanese/English voice credits, richer people pages, constellation search/zoom, inline trailers, daily radar and actionable chibi notices.

## Changed
- Discovery now includes only active GraphQL filter arguments; unused format, exclusion, search and numeric filters are omitted.
- HTTP 403 access denial is distinct from an expired sign-in. It does not trigger automatic retries or ask you to reauthenticate as a guaranteed fix.
- Retains minimal identity verification for login and sync, separate from optional profile statistics.

## Live API finding
A diagnostic request returned HTTP 200 for a minimal AniList query and HTTP 500 for the previous full discovery query. Follow-up isolation was blocked by AniList/Cloudflare with HTTP 403. The specific failing resolver/filter could not be confirmed; no access-control workaround was attempted. This change is defensive request hardening, not a claim that live AniList access is proven fixed.

Unit tests cover request construction, catalogue separation, voice credits and identity verification. Device navigation/migration/sync-acknowledgement checks run with emulator networking disabled; they do not validate live AniList loading. Live login/sync/data loading and phone notifications/battery still require phone verification.
